# Family Board – handoff ל-Claude Code

## מה יש כאן

- `SPEC.md` – האפיון המלא: שלוש השכבות (לו״ז, שגרות, משימות), ניקוד, תצוגות, מודל נתונים ב-TypeScript וכללי חישוב. שלב 1 ושלב 2 מסומנים.
- `screens/` – מסכים לדוגמה. רפרנס למבנה ולזרימה בלבד, לא לעיצוב.

## איך משתמשים

1. שומרים את התיקייה בתוך הפרויקט: `docs/family-board/`
2. מדביקים ב-Claude Code את הפרומפט שבהמשך.
3. אחרי כל שלב Claude Code עוצר ומסביר איך לבדוק. בודקים, מאשרים, וממשיכים.

## הפרומפט

```
אני מוסיפה ל-Family Board מערכת שגרות, משימות ולו״ז לכל בן משפחה.
האפיון המלא נמצא ב-docs/family-board/SPEC.md. קרא אותו כולו לפני שאתה מתחיל.
המסכים ב-docs/family-board/screens/ הם רפרנס למבנה ולזרימה בלבד, לא לעיצוב.

## המטרה
לבנות את שלב 1 מהאפיון ולשלב אותו בקוד הקיים. לא לבנות את שלב 2 (הסעות).

## עיקרון מרכזי: פונקציונליות קודם, עיצוב אחר כך
אנחנו סוגרים קודם את ההתנהגות. עיצוב יגיע בשלב נפרד, אחרי שהכל עובד.
- עיצוב מינימלי בלבד: פונט מערכת, רקע לבן, טקסט שחור, צבע הדגשה אחד.
- רכיבי HTML רגילים: button, input, select, checkbox. בלי ספריות UI חדשות.
- בלי אייקונים, איורים, אנימציות, צללים או גרדיאנטים. טקסט במקום אייקון.
- פריסה פשוטה: עמודות ורשימות. RTL ועברית בכל מקום.
- כל הסגנונות בקובץ אחד עם משתנים (צבעים, ריווח, גדלים), כדי שהחלפת העיצוב אחר כך תהיה במקום אחד.
- אם יש רכיבים קיימים בפרויקט, השתמש בהם כמו שהם. אל תשפר את העיצוב שלהם.

## לפני שאתה כותב קוד
1. סקור את הקוד הקיים וכתוב לי סיכום קצר: מבנה הפרויקט, מודל הנתונים הקיים, מה כבר קיים מתוך האפיון (בני משפחה, חיבור ל-Google Calendar, נקודות).
2. השווה למודל הנתונים באפיון. רשום מה מוסיפים, מה משנים, ואיך עוברים בלי לאבד נתונים קיימים.
3. האפליקציה רצה היום על המחשב, אבל "היום שלי" צריך לעבוד בעיקר בטלפון. הצע 2–3 דרכים לסנכרן נתונים בין המחשב לטלפונים, עם יתרונות וחסרונות. אל תממש עדיין.
4. הצע סדר עבודה לפי החלוקה שבהמשך.
עצור והמתן לאישור שלי.

## סדר עבודה: פרוסות שעובדות מקצה לקצה
כל שלב צריך לעבוד בפני עצמו: נתונים, לוגיקה ומסך בסיסי.
1. בני משפחה ושיוך יומני Google לבן משפחה (קריאה בלבד). תצוגת לו״ז ליום.
2. שגרות בחלון זמן: הכנסה, כללי ימים לשגרה ולצעד, מופע יומי, סימון צעדים.
3. "היום שלי": ציר זמן אחד שמשלב לו״ז ושגרות.
4. משימות: תאריך יעד, צירוף לשגרה, חזרה, תורנות.
5. שגרה גמישה, צעד בשעה מדויקת, חזרה במהלך היום.
6. ניקוד: יומן תנועות, ניקוד יומי, אישור הורה.
7. מסך מפוצל להורים ו"דורש טיפול".
8. הצעת צעד ע״י ילד, פרטיות.

## כללי עבודה
- בסוף כל שלב: עצור, כתוב מה נבנה, ומה בדיוק לבדוק (צעדים ללחיצה). המתן לאישור.
- כתוב בדיקות אוטומטיות לכללי החישוב מהאפיון (ruleApplies, stepApplies, בניית יום, רצף, מופע משימה הבא). כולל מקרי קצה: חופשה, מוצאי שבת, צעד עם ימים משלו.
- אם משהו באפיון לא ברור או סותר את הקוד הקיים, שאל. אל תנחש.
- אל תשנה התנהגות קיימת שלא קשורה לאפיון בלי לשאול.
- שמור את ההחלטות שמתקבלות בדרך בקובץ docs/family-board/DECISIONS.md.
```
